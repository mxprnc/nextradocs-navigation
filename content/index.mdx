### Websocket Streaming (진행 중 (중단))
주식 시세 서버 설계 시 Kubernetes 의 Headless Service 와 Statefulset 을 Redis 와 함께 활용해서 어떻게 웹소켓을 분산환경으로 스케일아웃할지에 대한 예제 시나리오 설계입니다. 아직 진행중이며, 아르바이트를 하느라 Codex 구독제를 중단해둔 상황이라 12월 중순 이후로 재개 가능합니다.

- Websocket-Streaming.pdf : https://github.com/mxprnc/nextradocs-navigation/blob/main/attachments/Websocket-Streaming-%EC%84%A4%EA%B3%84%EA%B0%9C%EC%84%A0.pdf

locust, k6, Gatling 등의 부하 테스트 도구와 Prometheus, Grafana 통해 어느 정도까지 네트워크 전송이 잘 되는지 직접 정량화된 테스트 결과를 기록해둘 예정입니다.

**설계를 위해 구성한 주요 구성요소**<br/>
**Simulator**
- Kafka 기반의 주식 시세 이벤트들을 Mocking 한 가상 시세 데이터 생성기입니다.
- Kafka 기반의 시세 스트리밍은 정상적이라는 가정하며 Mocking 한 시세 데이터 생성기로 해당 영역을 대체합니다.

**WS-Streaming**<br/>
Simulator 로부터 생성된 데이터를 WS-Streaming 으로 전송하면, WS-Streaming 은 다음의 역할을 수행합니다.
- 해당 Ticker 가 속한 Websocket Gateway 들을 Lookup 해서 찾아내는 역할을 수행
- 해당되는 Websocket Gateway 에 시세데이터 전달

**Websocket-Gateway (n)**<br/>
여러개의 Websocket-Gateway 는 n개의 Statefulset(e.g. 3\~20)으로 구성되어 있습니다. 하나의 Websocket Gateway 가 Ticker 하나에 대해 허용되는 Session 길이를 넘어서면, 다른 Pod 에서 Ticker 에 대해 세션을 구성합니다. 전송해야 하는 웹소켓 세션의 길이가 무한히 길어지는 증상과 병목을 해결하기 위해 세션을 여러 Pod 에 분산하며 세션리스트의 최대 길이를 특정 사이즈로 제한합니다.<br/>

일단 여기까지만 정리를 해두었고, 이 다음은 차차 정리해나갈 예정입니다. 이 프로젝트 진행 시에는 NestJS 와 Kubernetes 를 활용해 구성할 예정입니다.<br/>
